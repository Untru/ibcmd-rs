# Проверка SQL RPC для #376

Исполняемый файл Windows собран в профиле dev на Rust 1.95.0. SHA-256 исполняемого файла в замерах — `38f9f7fb92d11c7868b075e5c969055033d3958d6941e2590df6ff26df7e38f1`. Клиент запускал обычный `serve --stdio` и обменивался кадрами Content-Length. Использовались Windows authentication и отдельный SQL Server с проверкой сертификата через PEM только для тестового процесса.

## Импорт и состояние базы

Опциональный тест `cargo test --locked --test editor_server sql_import_and_pending_through_stdio -- --ignored --exact` прошёл. Для воспроизведения нужны `IBCMD_EDITOR_TEST_SERVER` и `IBCMD_EDITOR_TEST_DATABASE` (пустая стадия, имя `ibcmd_rs_376_<суффикс>`, содержимое штатной фикстуры tiny.cf). Тест записывает ConfigSave. Соединение, дерево, выгрузка, чтение, сверка, отказ без подтверждения, импорт с проверкой и чтение стадии выполнялись через RPC.

Лабораторная SQL-копия содержала семь упакованных строк основной части Format16 из `tests/fixtures/file-infobase/tiny.cf` (SHA-256 `da04d7a348e1b6e45ea703fe7363713dae4e71f9ea75322fcedd8bcec6d0b86a`). Строки перенесены в таблицы с нативными столбцами хранилища. Текст модуля до изменения совпал с нативной XML-выгрузкой, 166 байт. До подтверждения стадия была пуста. После подтверждения ConfigSave содержала изменённое тело, root, version и versions. Проверка вернула число сравнённых файлов больше нуля. Оба режима pending увидели стадию, подробный вернул вердикт без реструктуризации. Независимое чтение SQL обнаружило добавленный комментарий в распакованном теле. Применение к рабочей конфигурации проверяется отдельно.

Отдельная SQL-копия на сервере с недоверенным сертификатом дала `-32014` / `UnknownIssuer` для connect, короткого pending и подтверждённого import.

## Задержки

Время от отправки запроса до ответа в миллисекундах. Сначала один вызов каждого метода после соединения, затем пять циклов в том же процессе; в столбцах повторов — медиана. Кэши ОС не сбрасывались. Хост обслуживал другие задачи, выгрузка писала на занятый диск. Это наблюдения конкретного запуска.

Большая SQL-копия содержала все упакованные строки официального 1Cv8.cf **БСП 3.1.7.343**. SHA-256 `c7cc1a4d4d3b2c31feabcd899f9911dd4e160a684cf2de33593fee6e46186490`, 80 561 968 байт, Format15. В Config перенесены 6 301 файл (6 305 частей, 78 625 038 байт полезной нагрузки), ConfigSave пуста. Использован профиль экспорта 8.3.27. В каждом цикле текст чтения сравнивался побайтно с выбранной выгрузкой. Повторные выгрузки модуля заняли от 239 до 22 683 мс.

В том же запуске выгрузка первого документа в порядке tree/children шесть раз вернула `-32014` (`candidate set complete=false`). Первый отказ занял 5 473 мс. Успешная выгрузка документа и критерии ERP УХ остаются открытыми. Для оценок полноценной информационной базы нужны её нативная схема и данные. Выбранный SQL-импорт по одноразовому плану расширения зависит от #640.
