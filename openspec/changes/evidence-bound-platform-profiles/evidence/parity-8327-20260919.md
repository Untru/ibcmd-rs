# 8.3.27.2214 export and load parity, 2026-09-19

Measured before the profile change, with the release binaries of `master`
(c95b8ebc) and `feat/platform-8-5-support` (7c5e7ea7). Every write went to a
disposable clone; the source infobases were only read through `COPY_ONLY`
backups, and no cluster registration was changed.

## Environment

- Native oracle and cluster: `8.3.27.2214`, cluster `localhost:2541`, RAS `2545`.
- Disposable clones: `ibcmd_rs_bsp_8327_{native,ours}_20260919` from
  `BSP_Service`, `ibcmd_rs_uha_8327_{native,ours}_20260919` from `uha`
  (`1C:ERP. Управление холдингом` 3.3.3.3, compatibility `Version8_3_27`,
  configuration last saved by an 8.5.1 platform).

`--platform-profile platform-8.3.27.1989` against the 2214 cluster stopped at:

## Load

Native reference: `config support disable --force`, `config import files
--partial`, `config apply`. Without removing support the native import refuses
with «редактирование объекта метаданных ... запрещено»; the direct writer
ignores support state.

Both databases were then exported natively and compared.

- BSP, `exclusive`, three changes (common module body, common form module body,
  common form `Form.xml` title): only `ConfigDumpInfo.xml` (changed
  `configVersion` values) and `Ext/ParentConfigurations.bin` (support removed on
  the native clone only) differ; 12,196 files identical.
- BSP, `online` against native `apply --dynamic=force`: same result.
- ERP UH, `exclusive`, common module and common form module: 140,706 files
  identical. `CommonForms/ВводДаты/Ext/Form.xml` differs because the native
  partial import also imports the sibling `Form.xml` of the selected module,
  while the direct writer replaces module text only.

Timings: BSP 2.7 s, 5.5 s and 1.7 s per change against 11.1 s for the native
batch; ERP UH 56.6 s for the common module (50.9 s staging, the `versions` blob
is 4 MB) and 166.1 s for the form module (132.1 s bounded active export) against
57 s for the complete native batch.

### Refused before any write

- `Catalogs/_ДемоКонтрагенты/Ext/{ObjectModule,ManagerModule}.bsl`:
  `bounded export returned 4 rows for 2 exact storage identities`;
- `Catalogs/_ДемоКонтрагенты/Forms/ФормаЭлемента/Ext/Form/Module.bsl`:
  `missing existing top-level metadata owner descriptor`;
- `Catalogs/.../Commands/.../Ext/CommandModule.bsl`: the command owner XML does
  not exist in a hierarchical source tree;
- ERP UH `CommonForms/ВводДаты/Ext/Form.xml`:
  `unsupported metadata reference for source resolution: Form.StandardCommand.Close`;
- ERP UH `CommonForms/ВыборПутиКАрхивуФайловТомов`: `3 rows for 2 exact storage identities`;
- `_ДемоРасширение`: `only the clean published-to-published 8.3.27 transition
  (byte 30 = 0) is enabled`; `ServiceDesk` and `VAExtension`: `Configuration
  property DefaultRoles carries <non-empty reference>`.

The refused `_ДемоРасширение` run had already written 170 rows (205 KB) into
`ConfigCASSave`, which motivates the staging precheck in this change.

## SQL-level differences after an identical load

- Module bodies: the `info` and `text` elements are byte-identical, but the
  container element headers keep zeroed timestamps and a different page chain
  (5 pages native, 14 pages custom for the same 4,849 payload bytes).
- Form bodies: identical apart from two CRLF positions in the brace text.
- `Params`: native apply rewrites `789702c6-d272-4008-9e55-db6f10687ae0.ui`
  (23,386 -> 24,301 bytes) and `97f2c291-1aa3-4d96-8266-82a958c7dfaf.ui` (94
  bytes, new digest) on BSP, and creates an equivalent pair on ERP UH. The
  direct writer leaves them untouched. These are the same rows that the 8.5
  baseline identified as generation-selection state.
- `Files`: native apply rewrites `MobileVersions.dat`; the direct writer does not.
- `DBSchema`, `_ConfigChngR` and `_ConfigChngR_ExtProps` are identical.

## Family roundtrip sweep (custom import plus native apply)

Representative prefix per family, `--source-dir` set to the native export:

- BSP: 3 of 11 families `ok` (Enums, CommonModules, CommonCommands);
- ERP UH: 3 of 11 families `ok` (CalculationRegisters, CommonModules, CommonCommands).

The failures are managed-form facets (`ExcludedCommand`, `ListSettings`,
conditional appearance, DCS inside forms), base-free DCS template compilation
and `storage patch reason ... exceeding the 4096-byte bound`.

## Test suites

`cargo test --locked --workspace --no-fail-fast`: 3,261 passed and 20 failed on
`master`, 3,280 passed and 20 failed on `feat/platform-8-5-support`. The same 20
failures appear on both: 16 `mssql_dump` form and predefined-data assertions,
one CRLF-sensitive JSON snapshot, and three offline CF tests that do not expect
the emitted `ConfigDumpInfo.xml`.
