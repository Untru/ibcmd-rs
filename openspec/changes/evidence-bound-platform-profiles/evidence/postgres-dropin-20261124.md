# PostgreSQL в режиме подмены, #371

Стенд 24 ноября 2026 г. — Windows, PostgreSQL 17.2-4.1C, штатные
8.3.27.2342 и 8.5.1.1529. Для каждой сборки созданы отдельная база,
каталог `--data` и штатный эталон. Исходная ревизия master — `54b796f6`.

## Подготовка и состояние базы

Штатным `ibcmd infobase create --create-database` создана база PostgreSQL.
Для 8.3 использована `tests/fixtures/file-infobase/empty-xml-8.3.27`,
для 8.5 — `tests/fixtures/file-infobase/tiny-source`. После отдельного
штатного `infobase config import` обе команды вернули 0. Перед измерением
запрос к каждой базе подтвердил состав стадии:

```sql
SELECT (SELECT count(*) FROM config) AS active,
       (SELECT count(*) FROM configsave) AS staged;
```

| Штатная сборка | Активные строки | Строки стадии | Код штатного export | Файлов |
| --- | ---: | ---: | ---: | ---: |
| 8.3.27.2342 | 0 | 6 | 0 | 3 |
| 8.5.1.1529 | 0 | 8 | 0 | 5 |

Обе программы читают сохранённую конфигурацию. Прерванное применение
стадии в этот замер не входит.

## Командная строка и коды выхода

```text
ibcmd infobase config import --dbms=PostgreSQL "--db-server=127.0.0.1 port=5432" --db-name=<база> --db-user=postgres --data=<каталог> <исходники>
ibcmd infobase config export --dbms=PostgreSQL --database-server "127.0.0.1 port=5432" --database-name <база> --database-user postgres --data=<каталог> <эталон>
```

На обеих сборках `export` и `import` с флагами СУБД, сервера и пользователя
и пропущенным именем базы возвращают 2 с сообщением «Не указано значение
параметра: db-name». Раньше подмена начинала операцию и возвращала −1.
В YAML с одной секцией `database` и типом PostgreSQL проверены отсутствующие
`name` и `server`. До проверки позиционного пути штатная программа требует
соответственно `db-name` и `db-server`. Пустое значение, явно переданное как
`--db-name=` или `--db-server=` при указанном втором поле, позволяет дойти до
проверки пути.

Отдельные отрицательные контроли штатного экспорта дали −1 для
отсутствующей базы на рабочем сервере и для существующей базы с
`"--db-server=127.0.0.1 port=1"`. В последней диагностике обеих сборок
серверным адресом был именно порт 1. Штатная 8.3.27.2342 также вернула
−1 при попытке импортировать XML 2.21.

## Привязка платформы

На исходном master точная версия `--platform=8.3.27.2342` отклонялась с
кодом 2. Для сравнения с исправлением в `IBCMD_RS_CONFIG` задаются две записи:

```toml
[[database]]
server = "127.0.0.1 port=5432"
name = "<база 8.3>"
platform = "8.3.27.2342"

[[database]]
server = "127.0.0.1 port=5432"
name = "<база 8.5>"
platform = "8.5.1.1529"
```

Для каждой базы в `IBCMD_RS_PLATFORM` задаётся противоположная сборка.
Штатный эталон сравнивается с двумя выгрузками подмены — по привязке
и по явному `--platform=<точная сборка>`. При сравнении учитываются все
относительные пути и байты, включая `ConfigDumpInfo.xml`.

## Результат подмены

Собран `cargo build --locked --bin ibcmd-rs` на Rust 1.95.0, коммит
`1b1bf95d2b675d73d62198537705b9403957ee08`. SHA-256 исполняемого файла:
`8ae165271bb631450431599266fe1e31f0e268b3f0834fbe064b9d3258dd1c8f`.

| Проверка | 8.3.27.2342 | 8.5.1.1529 |
| --- | --- | --- |
| `settings show --json` при противоположном `IBCMD_RS_PLATFORM` | источник `database`, 8.3.27.2342, XML 2.20 | источник `database`, 8.5.1.1529, XML 2.21 |
| Экспорт по привязке, код и побайтовое совпадение со штатным | 0, 3/3 | 0, 5/5 |
| Экспорт с точным `--platform`, код и совпадение | 0, 3/3 | 0, 5/5 |
| Импорт копии штатного дерева с изменением комментария конфигурации | 0 | 0 |
| Пропущено имя базы, export / import | 2 / 2 | 2 / 2 |
| Экспорт отсутствующей базы на рабочем сервере | −1 | −1 |
| Экспорт существующей базы с закрытым портом 1 | −1 | −1 |

Для привязанной к 8.3 базы импорт дерева 2.21 вернул −1. Для каждого
успешного экспорта использован новый каталог. Контрольные суммы штатного
дерева и обеих выгрузок подмены совпали. SHA-256 вычислен по записи для
каждого отсортированного относительного пути: UTF-8 пути с разделителем
`/`, нулевой байт и 32 байта SHA-256 файла.

- 8.3.27.2342 — `0f440f1bc8f64946d11a0a983f8bd3339b1885e58ea5ad3e4f8b661180ae64e4`.
- 8.5.1.1529 — `2ac7955064ac1251969bff3795c27cceec0567ced9ccd0f343d4e3e9f5de129a`.
