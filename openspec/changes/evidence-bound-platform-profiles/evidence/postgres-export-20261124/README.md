# Выгрузка поставочной БСП из PostgreSQL (#369)

## Вход и воспроизведение

Для каждой сборки платформы используется отдельная одноразовая база PostgreSQL
17.2-4.1C x64 с кодировкой UTF-8 и сортировкой Russian_Russia.1251.
Исходный CF БСП 3.1.11.309 взят из официальной поставки. Размер 67 167 823
байта, SHA-256 `4ded13b6b6b5c74f11c544e6be442cbea6f49eb8dede3424841b4bd6af4b4448`.

Проверяемый бинарник ibcmd-rs 0.4.1 собран с `--release --locked` из
`54b796f64da5daed3714acdf7810581fe0e58778`, SHA-256
`f62f0728337ca655a5fab5863ed55813eb7dba2044ee8106e2ddc64341aee3ab`.
Команды ниже используют один сервер, одну базу и один CF внутри каждой пары.
Параметр `<профиль>` задаёт версию XML целевой платформы.

```text
initdb -D <кластер> -U <пользователь> --encoding=UTF8 --locale=Russian_Russia.1251
ibcmd infobase create --create-database --dbms=PostgreSQL --db-server=<сервер> --db-user=<пользователь> --db-name=<база> --data=<рабочий-каталог>
ibcmd infobase config load --dbms=PostgreSQL --db-server=<сервер> --db-user=<пользователь> --db-name=<база> --data=<рабочий-каталог> <БСП.cf>
ibcmd infobase config export --dbms=PostgreSQL --db-server=<сервер> --db-user=<пользователь> --db-name=<база> --data=<рабочий-каталог> <штатный-каталог>
ibcmd-rs infobase config export --dbms=PostgreSQL --db-server=<сервер> --db-user=<пользователь> --db-name=<база> --platform=<профиль> <каталог-кандидата>
python compare.py <штатный-каталог> <каталог-кандидата>
```

Скрипт сравнения требует Python 3.12+. Он сопоставляет точные относительные
имена, сравнивает содержимое блоками по 1 МиБ и считает односторонние файлы.
В SHA-256 дерева входят для каждого файла в порядке сортировки относительного
имени его путь в UTF-8 с разделителем `/`, байт NUL и 32 байта SHA-256 файла.
`ConfigDumpInfo.xml` участвует наравне с остальными файлами.

## Проверка входа перед экспортом

Штатные `create` и `config load` завершились с кодом 0 на обеих сборках.
Каждая пара читает законченную стадию того же CF. Между загрузкой и
экспортом `config apply` не выполняется.

| Штатная платформа | Профиль ibcmd-rs | Строк в config | Частей в configsave | Имен в configsave |
|---|---|---:|---:|---:|
| 8.3.27.2342 | 8.3.27 | 0 | 7 212 | 7 209 |
| 8.5.1.1529 | 8.5.1.1529 | 0 | 7 212 | 7 209 |

Для штатного 8.3.27.2342 выбран профиль линии 8.3.27 с XML 2.20.
Отдельный вызов этого же бинарника с `--platform=8.3.27.2342` вернул код 2
при разборе аргументов. В списке известных версий указана линия 8.3.27.
Для 8.5 использован профиль точной сборки. Счётчики сняты после выхода
процесса загрузки и включают части с ненулевым номером.

```sql
SELECT (SELECT count(*) FROM config) AS config_rows,
       count(*) AS staged_parts,
       count(DISTINCT filename) AS staged_names
FROM configsave;
```

Во время подготовки одноразовых баз использовался `fsync=off`. Перед замерами
параметр возвращён к `on`, контрольная точка вынесена за интервал экспорта.

## БСП на 8.3.27.2342

Обе команды завершились с кодом 0 в каждом из двух зачтённых запусков.
Первую пару запустили в порядке ibcmd → ibcmd-rs, вторую — в обратном порядке.

| Пара | ibcmd 8.3.27.2342, с | ibcmd-rs с профилем 8.3.27, с | Побайтовая сверка |
| --- | ---: | ---: | --- |
| 1 | 878,6 | 385,1 | 9 156 совпадений, 0 различий, 0 односторонних файлов |
| 2 | 561,0 | 381,2 | 9 156 совпадений, 0 различий, 0 односторонних файлов |

SHA-256 всех четырёх деревьев —
cb9f5b5807aac853864b301c4ad8771fdae480cb72d3ed0fd8e6d61cd9681cf2.
Отпечатки PostgreSQL совпали до и после экспортов, в том числе после сбоя
хоста. После восстановления кластер продолжил работу на другом локальном
порту. Два штатных запуска пересеклись с тяжёлыми процессами и были исключены.

## БСП на 8.5.1.1529

Штатный ibcmd 8.5.1.1529 и ibcmd-rs с профилем 8.5.1.1529 завершились
с кодом 0. Совпали все 9 156 файлов, включая ConfigDumpInfo.xml.
Оба дерева имеют SHA-256
`4a3c73f7f28fd6eacbb0ea06285e21bd63ae9d893bda6eb7a872478033998bc4`.

Оба экспорта выполнены на C: из той же стадии PostgreSQL. Наблюдаемое
время составило 15,54 с у штатного ibcmd и 10,55 с у ibcmd-rs. Между
запусками кластер перезапускался, поэтому для вывода о сравнительной
скорости нужен последовательный замер в одном окне.

## ERP УХ

Для оставшейся матрицы доступен официальный CF «1С:ERP. Управление
холдингом» 3.3.5.1, проверенный в рамках #367. Требуются одноразовые
стадии PostgreSQL, штатные и альтернативные экспорты на обеих сборках,
побайтовое сравнение файлов и замеры времени.
