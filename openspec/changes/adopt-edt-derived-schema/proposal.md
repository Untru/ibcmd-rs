# Предложение: перейти на EDT-derived schema-first архитектуру

## Зачем

Последний этап достижения побайтового паритета остановился: локальные исправления
XML-сигнатур смешивают декодирование SQL/blob, восстановление модели и
сериализацию. Правила порядка, значений по умолчанию и версионных ограничений
угадываются по отдельным файлам и накапливаются в крупных условных парсерах.

Локальное исследование EDT 2025.2.3 показало, что его model/import/export bundles
содержат пригодный для независимой реализации источник структуры моделей и
точных правил writer-классов. EDT должен использоваться только в исследовательской
лаборатории; собранный производный corpus хранится в репозитории и работает без
установленной EDT.

## Что меняется

- Добавляется независимый workspace-crate `ibcmd-schema`.
- В репозиторий включается очищенный EDT-derived индекс моделей, импортёров и
  экспортёров без JAR, bytecode и абсолютных путей.
- Проверенные правила writer-классов фиксируются в машинно читаемом corpus с
  происхождением и условиями применимости.
- `ibcmd-xml` получает зависимость от `ibcmd-schema`; XML-слой становится
  потребителем правил, а не владельцем локальных эвристик.
- Добавляется воспроизводимый исследовательский импортёр для обновления corpus,
  но он не участвует в build/runtime.
- GitHub backlog перестраивается вокруг архитектурных слоёв и трёхстороннего
  oracle `IBCMD / EDT / ibcmd-rs`.

## Не входит в первую поставку

- Копирование или распространение JAR, native libraries и bytecode EDT.
- Запуск EDT из production-кода.
- Мгновенный перенос всех 3 902 типов в типизированные Rust-структуры.
- Объявление полного паритета до прохождения УТ и БСП с `0/0/0`.

## Результат

Репозиторий содержит автономный, версионированный и проверяемый источник знаний,
на который можно последовательно переводить metadata, forms, DCS и MXL writers.
