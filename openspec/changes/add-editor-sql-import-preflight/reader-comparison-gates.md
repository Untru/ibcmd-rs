Native source baseline: `aa22ac9eafc3bb9f655c3e41a9e9028e58ba8fa79a633090a20b9b4c08d4cac4`.
No source provisioning is needed. All execution belongs to the sole operator
under a new idle/freeze/lease receipt; this document executes nothing.

The original strict capture plan requires a product candidate commit/binary tuple.
No applicable deployed product binary is established for this script-only
measurement. Compiler/test binaries and older unrelated product receipts must
not fill that field. Before measurement, review an additive strict measurement
plan kind with actual executed script/runtime/native/source/freeze provenance,
explicit product_executed=false and no accepted-profile/write authority. All
identity/schema/parts/nonce/count/budget/resultset/disposal checks stay required;
the original candidate-bound plan must not silently accept missing candidate
fields. Candidate comparison retains its separate exact binary requirement.
Required source controls reject cross-kind substitution, unknown kinds/fields,
missing executed-runtime/source/native-baseline/freeze bindings and a fabricated
product tuple in a measurement-only envelope. A measurement receipt cannot
satisfy product execution evidence or a later accepted-profile requirement.

1. Pin the reviewed #359 wrapper/control/capture.sql/validator and trusted Python
   hashes, actual Windows5.1 conversion-only receipt and exact generated plan.
   Open one dedicated non-pooled connection in the existing authorized context;
   no reconnect/provider/security fallback. Actual target identity/native output
   hashes come from the baseline manifest. Bind the current freeze window.
2. First strict metadata measurement may use P1=NULL only in the reviewed
   measurement capture. All identity/nonce/count/SPID/transaction seals, budgets,
   empty CONFIGSAVE resultset and schema serializer/hash checks remain required.
   Keep raw metadata/header/part fingerprints and files in the VM; export only
   bounded sanitized receipts/digests. A failed/incomplete request returns no
   usable measurement and never triggers an automatic repeat.
3. Separately assign the exact candidate binary and embedded revision, clean
   source/features/lockfile/build receipt, command/API route and fixed operator
   settings/auth mechanism. A fake runner, native executable or source commit
   hash cannot stand in for that candidate provenance. #380 RPC and #382 snapshot
   routes have separate actual reviewed packets; no target overrides are added.
4. After explicit measured-profile review, an allocated read-only candidate run
   must bind the same identity/schema under a new coherent snapshot. Compare
   cumulative table/part/key/header/size/payload hashes, additions/deletions and
   explicit empty staging to the operator oracle while the freeze still holds.
   Different hash domains need an explicit canonical comparison definition;
   never equate an ordered observer digest with a canonical packed-map digest.
   Any profile/identity/readset mismatch refuses before further candidate work.
5. Candidate/native source comparison is computed inside the VM using the exact
   pinned profile and inventory rules, with CDI membership/versions treated
   separately and no broad omitted-file whitelist. Retain before/after target
   fingerprints, native artifact hashes and source witness. Payload/XML never
   leave the VM as an accidental comparison artifact. No repeated native apply
   is part of this read-only gate.
6. Acquire separate evidence for actual cancellation/provider resultset
   numbering/disposal and concurrent-writer lock/coherence controls. A successful
   baseline capture does not prove these fault paths, atomic publication or TLS.
   Shared-memory integrated metadata does not establish network TLS or #380
   Rust settings/auth binding.

Every stage reports its exact tuple and what ran; current diagnostic compiler
results always remain publication_allowed=false. Neither successful capture nor
reader comparison registers an accepted writer profile, constructs selected-key
mutation authority, enables a SQL import RPC, or proves full module/form import
apply/export acceptance. Worker lifetime, complete owner/role/parent evidence,
origin-aware versions, full readset CAS and strict directory membership gates
remain required for that later work.
