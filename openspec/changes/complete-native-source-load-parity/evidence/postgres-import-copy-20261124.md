# PostgreSQL — загрузка ConfigSave через COPY (#370)

## Протокол записи

На исходном master `54b796f6` обычная команда `infobase config import` для
`tests/fixtures/file-infobase/tiny-source` завершилась успешно на тестовом
сервере протокола PostgreSQL. Между `DELETE FROM configsave` и `COMMIT`
клиент отправил восемь отдельных запросов `INSERT`. Запросов `COPY` было ноль.

После изменения импорт XML и загрузка CF используют один
`COPY configsave (...) FROM STDIN WITH (FORMAT csv)` на всю стадию.
Момент записи берётся из `LOCALTIMESTAMP(0)` в той же транзакции.
Регрессионные тесты находятся в `src/postgres_infobase.rs`.

Отдельная проверка клиента на PostgreSQL 17.2-4.1C использовала временную
таблицу с первичным ключом и полем `bytea`. В первую транзакцию передали
ключ с запятой и кавычкой, два байта `00ff` и вторую строку со 131 073
байтами `ab`. Во второй транзакции после удаления исходных строк сервер
отклонил COPY с повторяющимся ключом (SQLSTATE `23505`). После отката то же
соединение вернуло оба исходных ключа, длины и проверенные префиксы данных.

В отдельном прогоне триггер `BEFORE INSERT` пропустил одну из двух строк
через `RETURN NULL`. PostgreSQL успешно завершил команду с `COPY 1`.
На коммите `28e63362` клиент принял такой ответ. Исправленный клиент
обнаружил расхождение с двумя отправленными строками. После отката
проверка прочитала прежние значения из обеих строк.

## Контроль исходного импорта, 8.3.27.2342

В пустую информационную базу PostgreSQL 17.2-4.1C загрузили
`tests/fixtures/file-infobase/empty-xml-8.3.27` бинарником master
`54b796f6`. Создание базы, импорт, штатное применение
`ibcmd infobase config apply --force` и штатная выгрузка дали код 0.

| Момент | config | configsave |
|---|---:|---:|
| До импорта | 0 | 0 |
| После импорта | 0 | 6 |
| После применения | 5 | 0 |

Полная побайтовая сверка дала 2 из 3 файлов. Пути совпали.
Различался только `ConfigDumpInfo.xml` (316 и 640 байт).
SHA-256 исходного дерева — `1790dbacedf1450db2fbe792eb52636d17b7717bf3383a10a4a746d0ddaa7645`,
выгрузки — `97f7724511e983d74ae58f3f41584083d9f2d704eea849beae3702ef82497dd2`. Хеш дерева вычислен по отсортированным
относительным путям с разделителем `/`: UTF-8 пути, нулевой байт и 32
байта SHA-256 содержимого каждого файла.
