## Public API and isolation
Call file_import::prepare_guarded_with_source_limits for every preparation, including final-policy stage-count controls, inspect Plan::summary, and consume Plan::publish_guarded with CURRENT target. The API owns stored_objects::exclusive; never nest that lock. Keep finite target ReadLimits and source SourceInventoryLimits. No direct WriteSession::replace is a positive oracle; it is only external-conflict setup.

A parent test performs no metadata compilation. Each exact child streams logs immediately to retained files, has a 300-second timeout and a polled 16 MiB per-stream budget; oversized logs are never read into RAM or accepted. Polled file budgets can overshoot burst writes and are not hard disk quotas. A hosted outer runner also bounds and stops the parent process tree; this does not imply a new production process policy. Each prepare/publish compiler stage and each changed-CF inspection runs in a separate exact invocation of the same hashed test executable, with a strict child sentinel/phase/owned-root marker and1 selected/0 ignored result. The named parent test dispatches to its own child phase, avoiding a helper-only passing test. Stage1 and stage2 share exactly one fresh owned DB but have distinct child TMP/TEMP/TMPDIR. No metadata-global reset or process-wide environment mutation. This does not test persistent multi-RPC compiler reuse; that remains a separate hard gate.

Final policy rejection and late cancellation run through publish_guarded: bounded descriptor-control path has guard calls1 session-open,2 initial replace gate,3 final gate after verified copy; reject/set cancel only at3. A same-directory canonical-prefix rename probe first proves replacement succeeds without a handle, fails with a read/no-DELETE destination handle (measured WinError5 or32, source/target bytes preserved), then succeeds after drop. A separate retained no-delete real backup handle must yield the SAME measured error in actual post-database-publication Error::Published, without a production hook; require Error::Published, committed edited state, exact retained original recovery image and unchanged old backup, with no retry/rollback. Concurrent cancellation after commit is not deterministically injected by this harness; existing finish_publication unit priority coverage stays distinct.
