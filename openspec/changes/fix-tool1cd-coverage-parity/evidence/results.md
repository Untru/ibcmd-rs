# Результаты исследования tool1cd и проверки Coverage

Задача: [#570](https://github.com/Untru/ibcmd-rs/issues/570). Источник формата: [tool1cd, закреплённый commit](https://github.com/jjzhang166/tool1cd/tree/7c4b91cb7a7bb48a32be00b9f32afe740dada6e1).

## Что исправлено

- Метаданные: флаги общих реквизитов, история констант и планов обмена, свойства бизнес-процессов и задач, вид редактирования и быстрый выбор планов видов расчёта, стандартные команды и справка регистров расчёта.
- Представление: независимые объявленный вид элемента стиля и тип его значения, пустой адрес WSReference, подтверждённые цвета, стандартные картинки, клавиша Space и режим индикатора BrokenTilt. Команда AddAutoSelectedField допускается только в доказанном контексте настроек динамического списка.
- Макеты: счётные структуры разрывов страниц, тип бумаги, высота AutoFont, промежуток линии, виды штриха и фигуры, OEMFixedFont, GIF87a/GIF89a, одиннадцать параметров печати графической схемы и пустая HTML-справка.
- Неизвестные значения в распознанном формате отклоняются. Добавлены проверки полного чтения повреждённых записей, включая неизвестные UUID вида линии; восстановление старым декодером не должно обходить отказ.

Факты enum и координат из tool1cd сопоставлены с публичными CF Coverage. Сам tool1cd не описывает грамматику MOXCEL: правила разрывов, групп строк/колонок, бумаги, AutoFont и части параметров печати подтверждаются отдельно нативными CF и существующим декодером. Код tool1cd, прикладные объекты и приватные базы в изменение не копировались.

## Что ещё осталось

Среди оставшихся групп: современные профили элементов форм и команд, контекст ссылок и событий, шрифты TitleLevel1/4 с версией источника, дополнительные индексы, ресурсы форм, оболочка расширений в SQL, языковые имена СКД и смешанные ссылки справки. Старое описание tool1cd не даёт достаточной информации для безопасного решения этих правил; нужны отдельные нативные минимальные случаи.

Для Task полное исходное XML сравнивается в обе стороны, но два внутренних UUID не представлены в XML. Компилятор сохраняет прежнее поведение с Nil в этих полях. Проверка не обещает побайтового сохранения физического владельца или SQL для этого случая; граница явно названа в schema и тесте.

В этом измерении SQL не изменялся. Компиляция XML в записи и чтение записей не подтверждают принятие их SQL-платформой. Полное SQL import/apply остаётся отдельной проверкой. Issue #570 остаётся открытым, пока эти критерии не подтверждены.

## Воспроизведение

- `cargo test --locked -p ibcmd-rs --lib tool1cd_ --no-default-features`
- `cargo test --locked -p ibcmd-rs --test coverage_corpus --no-default-features -- --nocapture`
- `cargo test --locked -p ibcmd-rs --test coverage_storage_records --no-default-features -- --nocapture`
- `python tools/coverage/measure_corpus_cases.py --ibcmd-rs <binary> --root tests/fixtures/coverage --out <new-directory>`; выбранные 44 набора перечислены в measurements.json.
- `cargo xtask check`, затем `cargo xtask ci`; точные итоговые статусы указываются после завершения, в PR.

Эталоны расширяются только полными подтверждёнными совпадениями, без удаления прежних обещаний. Маршрут выгрузки сохранённых записей дополнительно закреплён 136 путями в 19 наборах, только для успешных выгрузок.
