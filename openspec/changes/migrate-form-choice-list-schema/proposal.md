# Предложение: schema-driven ChoiceList и ListSettings

## Зачем

Форма всё ещё смешивает физические slot-координаты с решениями XML writer.
Это делает локальные исправления зависимыми от конкретного blob и мешает
переиспользовать доказанные правила.

## Что меняется

- ChoiceList получает каноническое представление с provenance.
- Порядок, default и version gate читаются из `ibcmd-schema`.
- ListSettings передаётся DCS-слою как типизированное значение.
- Перекрытые строковые нормализаторы и object-specific условия удаляются.

## Результат

Выбранный срез проходит raw → canonical → schema writer без влияния числового
slot на XML order и без регрессий на УТ/БСП cohort.
