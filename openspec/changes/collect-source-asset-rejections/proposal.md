# Предложение: пакетный сбор отказов source assets

## Зачем

Полный экспорт УТ сейчас останавливается на первом
`DetailedFormBodyExtraction::Rejected`. Из-за этого один дорогостоящий прогон
показывает только один новый raw-профиль, хотя уже существующий отчёт
`SourceAssetCompletenessReport` умеет хранить безопасные структурированные
диагностики opaque-значений.

## Что меняется

- Добавляется явный full-scope диагностический режим
  `--collect-all-source-asset-diagnostics`.
- В этом режиме только типизированные form-writer rejections с непустой
  структурированной диагностикой становятся `not emitted`, а обход остальных
  строк продолжается.
- Ошибки SQL/BCP, I/O, контейнера, парсинга без структурированной диагностики и
  внутренние инварианты остаются fatal.
- Отчёт source assets получает детерминированные bounded-кластеры без raw
  payload.
- Строгий `--require-complete-source-assets` не меняется: после полного обхода
  partial-отчёт по-прежнему завершает команду ошибкой.
- Если одновременно включён строгий gate корневых метаданных, его evidence
  также записывается до финального отказа; ошибки обоих gate'ов собираются, а
  не обрывают диагностический проход по первой проверке.
- Parity-скрипт сохраняет диагностический manifest даже при ожидаемом
  завершении strict gate с ненулевым кодом.

## Влияние

- `src/cli.rs`
- `src/infobase.rs`
- `src/mssql_dump/mod.rs`
- `src/mssql_dump/source_assets.rs`
- `scripts/export-ibcmd-vs-ours.ps1`
- связанные Rust и Pester-тесты

Изменение не разрешает эмиссию неполного `Form.xml` и не делает partial run
release-eligible.
