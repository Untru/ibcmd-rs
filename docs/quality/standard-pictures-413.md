# Сравнение выгрузок при объединении таблиц стандартных картинок

Для [#413](https://github.com/Untru/ibcmd-rs/issues/413) сравнивались две соседние ревизии из истории [#422](https://github.com/Untru/ibcmd-rs/pull/422). Родитель `fdb4359e8cf9f35e1e8a7754091cb738e1380555` содержит две таблицы. Коммит `c777b40cb1d272bda7a6ac6d487180858ce8d80b` переводит читателей на общую таблицу из 218 пар. Такая пара изолирует изменение от остальных правок большого PR.

Обе сборки сделаны на Windows командой `cargo build --locked --profile iter --features platform-oracle --bin ibcmd-rs`, Rust 1.96.0. SHA-256 исполняемых файлов в порядке «до», «после»:

```text
d18819126de4d032416e48985ab0f3ed474c14a8fa7739039254d303b23d6dc4
b297a6b6878c72c3ed12b684f9685745ab3f51b39fff601ab9bc8fa0eab8c2fe
```

## БСП на одинаковых строках

Из одного CF БСП 3.1.11.309 функцией `ibcmd_cf::archive::decode_packed_archive` извлечены все 7 209 элементов. Каждый исходный упакованный payload записан под именем `<имя элемента>__part0.bin`. Обе сборки читают один каталог строк. Для каждого запуска использован новый каталог вывода.

```text
ibcmd-rs mssql-dump-config --rows-dir ROWS -o OUTPUT --extract-module-text --extract-metadata-xml --no-binary-rows --source-version VERSION
```

Сравнение учитывает множество относительных путей и SHA-256 исходных байтов каждого файла. Хеш дерева — SHA-256 конкатенации записей, отсортированных по относительному пути: путь с разделителем `/` в UTF-8, нулевой байт, 32 байта SHA-256 файла. Хеш каталога строк — `b2e4dcdcad74570ae54695a1146ddabfb19659f7a7c3629446daba389eb24ca5`.

| Формат XML | Код до / после | Файлы исходников до / после | Изменено / пропало / добавлено | Общий SHA-256 исходников |
|---|---|---:|---|---|
| 2.20 | 0 / 0 | 9 156 / 9 156 | 0 / 0 / 0 | `cb9f5b5807aac853864b301c4ad8771fdae480cb72d3ed0fd8e6d61cd9681cf2` |
| 2.21 | 0 / 0 | 9 156 / 9 156 | 0 / 0 / 0 | `2f22a52af7fd9330bae375fcfb52eb0c5e487b48e850132935f2a4f25406f332` |

Служебный `manifest.json` также совпал в обеих парах. SHA-256 входного CF — `4ded13b6b6b5c74f11c544e6be442cbea6f49eb8dede3424841b4bd6af4b4448`. Прямой `cf export` того же CF дал те же хеши исходников, что и экспорт строк. Для 2.20 этот хеш совпал и с сохранённой штатной выгрузкой 8.3.27.2214. Это воспроизводит опубликованный результат БСП 9 156/9 156 и добавляет изолированное сравнение. [Замер от 23 октября](https://github.com/Untru/ibcmd-rs/issues/413#issuecomment-6360769092).

## УХ и исходный лабораторный корпус

При чтении сохранённой штатной выгрузки «Управление холдингом» 3.2.1.116 (8.3.27.2214) проверены 86 231 файл, включая 60 562 XML. В XML нет ни одного из шести имён ИТК, перечисленных в #413. Поиск выполнялся по точной ссылке `StdPicture.<имя>` с проверкой границы имени. SHA-256 штатного дерева — `bdd5235ea1ce464c0b53821d1fa6d80224f2eb6ea3519b152448f22b9e4cb88e`.

При сравнении с сохранённым локальным экспортом того же шаблона совпал 84 521 файл, различаются 1 432, отсутствуют 278, лишних 0. Его отчёт содержит 48 отказов экспорта записей. Ревизия этой сборки не установлена. Такой замер показывает границу доступного эталона. Причина расхождений и влияние изменения таблицы на них не установлены.

Исходная лаборатория использовала ERP УХ с 140 709 файлами и БСП с 12 198 файлами на 8.3.27 и 12 337 на 8.5. Для четырёх расширений БСП ранее опубликовано сравнение со штатным экспортом на 737 файлах (3 + 185 + 465 + 84). Эти результаты относятся к другой паре ревизий. Для закрытия #413 остаются сравнение на исходных снимках строк БСП двух платформ, четыре исходных расширения БСП и экспорт исходного УХ 8.3.27 под общей лабораторной блокировкой. [Описание исходных измерений](../extensions/parity.md#database-export-results), [план приёмки](physical-adapter-387-review.md#g2-one-standard-picture-table-not-in-04-413).

## Расширения и внешние файлы

Команда для каждого входа и каждой из двух сборок — `ibcmd-rs cf export INPUT OUTPUT --source-version VERSION`. В сравнении с сохранёнными штатными деревьями исключён служебный маркер стенда `.complete`. В сравнении до и после учтены все файлы.

| ИТК, вариант CFE | Совпало до/после в 2.20 | Совпало до/после в 2.21 | Отличается от штатной 8.3.27.2214 / 8.5.1.1529 |
|---|---:|---:|---|
| NO_SSL | 2 428 | 2 428 | 4 / 4 |
| SSL_ENG | 2 443 | 2 443 | штатных деревьев на стенде нет |
| SSL_RU | 2 453 | 2 453 | 5 / 5 |
| SSL_RU_open | 2 453 | 2 453 | 10 / 9 |

Все восемь пар CFE завершились с кодом 0. Между ревизиями совпали пути и содержимое всех файлов. На трёх вариантах со штатными деревьями различаются байты по указанному числу путей, состав файлов совпадает.

Весь локальный внешний корпус (75 EPF и 36 ERF) проверен в формате 2.20 против штатных выгрузок 8.3.27.2214 из конфигурационной базы. Между ревизиями совпали все 1547 файлов, включая набор путей. Коды выхода также совпали: код 0 у 111 входов. Относительно штатных деревьев совпало 1520, различается 27, отсутствует 0, лишних 0. Из 1 519 файлов в `tests/fixtures/external/corpus-baseline.txt` потеряно 0.

Для повторной проверки агрегата отсортируйте выгрузки по SHA-256 входного файла (hex в нижнем регистре) и версии XML. Для каждой добавьте в SHA-256 ровно 32 байта хеша входа, ASCII-версию (`2.20` или `2.21`), нулевой байт и 32 байта хеша дерева по описанному выше правилу. Итог одинаков до и после:

| Корпус | Деревьев на ревизию | SHA-256 агрегата |
|---|---:|---|
| ИТК | 8 | `b73f0d4ee8357f8883aa3c9bb79163abca28573cb59906144e361ac7486b160b` |
| EPF/ERF | 111 | `91fda6c3494510419c4c142bf1e600a9d1bd1db74610a5f845655b837b9fb8e3` |

Отдельно прошли оба теста исторического `cf_corpus.rs`, включая проверку размеров, SHA-256 и структуры двух внешних CF из закреплённого манифеста при заданном `IBCMD_CF_EXTERNAL_CORPUS`. Три теста исторического словаря прошли. В исходном отчёте по #413 для Монитора опубликованы 1 088/1 089 одинаковых файлов и проверка всех шести добавленных картинок; Монитор повторно в этот прогон не входил. [Ранее опубликованный замер](https://github.com/Untru/ibcmd-rs/issues/413#issuecomment-6360769092).

## Граница #725

В [PR #725](https://github.com/Untru/ibcmd-rs/pull/725) измерены семь дополнительных картинок и представление пустой ссылки справочника. На 8.3.27.2214 и 8.5.1.1150 там проверены три именованных корпуса и семь форм на каждой версии в цепочке XML → CF → XML. Для полного корпуса управляемых форм в описании оставлены отказы других свойств и ConfigDumpInfo. Сравнение выше фиксирует состояние до и после исторического `c777b40c`; изменения #725 в обе сборки не входят.
