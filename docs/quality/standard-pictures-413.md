# Сравнение выгрузок при объединении таблиц стандартных картинок

Для [#413](https://github.com/Untru/ibcmd-rs/issues/413) сравнивались две соседние ревизии из истории [#422](https://github.com/Untru/ibcmd-rs/pull/422). Родитель `fdb4359e8cf9f35e1e8a7754091cb738e1380555` содержит две таблицы. Коммит `c777b40cb1d272bda7a6ac6d487180858ce8d80b` переводит читателей на общую таблицу из 218 пар. Такая пара изолирует изменение от остальных правок большого PR.

Обе сборки сделаны на Windows командой `cargo build --locked --profile iter --features platform-oracle --bin ibcmd-rs`, Rust 1.96.0. SHA-256 исполняемых файлов в порядке «до», «после»:

```text
d18819126de4d032416e48985ab0f3ed474c14a8fa7739039254d303b23d6dc4
b297a6b6878c72c3ed12b684f9685745ab3f51b39fff601ab9bc8fa0eab8c2fe
```

## БСП на одинаковых строках

Из одного CF БСП 3.1.11.309 функцией `ibcmd_cf::archive::decode_packed_archive` извлечены все 7 209 элементов. Каждый исходный упакованный payload записан под именем `<имя элемента>__part0.bin`. Обе сборки читают один каталог строк. Для каждого запуска использован новый каталог вывода.

```text
ibcmd-rs mssql-dump-config --rows-dir ROWS -o OUTPUT --extract-module-text --extract-metadata-xml --no-binary-rows --source-version VERSION
```

Сравнение учитывает множество относительных путей и SHA-256 исходных байтов каждого файла. Хеш дерева — SHA-256 конкатенации записей, отсортированных по относительному пути: путь с разделителем `/` в UTF-8, нулевой байт, 32 байта SHA-256 файла. Хеш каталога строк — `b2e4dcdcad74570ae54695a1146ddabfb19659f7a7c3629446daba389eb24ca5`.
