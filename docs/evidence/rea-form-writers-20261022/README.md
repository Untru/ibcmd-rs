# Правила писателей XML форм из `mngbase.dll`

Дата: 22.10.2026. Ветка: `feat/rea-form-property-inventory-20261022`.

## Зачем

При выходе новой платформы `ibcmd-rs` должен быстро понять, что изменилось в
XML-выгрузке форм. Раньше это выяснялось диффом выгрузок. Здесь порядок и
умолчания снимаются из кода платформы: писатель элемента вызывает
`write_attribute(writer, 0xID, value)` в фиксированном порядке и пропускает
значения по умолчанию.

## Инструмент

`tools/rea/form_writer_rules.py`:

```powershell
# снять правила с одной платформы
python tools/rea/form_writer_rules.py extract `
  --dll "C:/Program Files/1cv8/8.5.1.1529/bin/mngbase.dll" `
  --elements UsualGroup Table Button Field `
  --out docs/evidence/rea-form-writers-20261022/8.5.1.1529.json

# сравнить две версии
python tools/rea/form_writer_rules.py compare `
  --left .../8.3.27.2214.json --right .../8.5.1.1529.json --out diff.md

# сводная матрица по каталогу
python tools/rea/form_writer_rules.py matrix --dir .../rea-form-writers-20261022 --out matrix.md
```

Как работает: строка-имя элемента → `xrefs` → границы функции по `.pdata` →
декомпиляция → разбор вызовов `write_attribute` у объекта, создавшего элемент,
вместе с условиями `!= default`.

Требуется REA с Ghidra (`GHIDRA_INSTALL_DIR`). На слабой машине поднимайте
`REA_GHIDRA_STARTUP_TIMEOUT_MS` и не запускайте больше двух анализов сразу.

Правила стабильны внутри ветки 8.3.x и внутри 8.5.1; переход 8.3.27 → 8.5.1
добавляет 8–13 атрибутов на элемент. Подробности — [matrix.md](matrix.md) и
[diff-8.3.27-to-8.5.1.md](diff-8.3.27-to-8.5.1.md).

Отдельное наблюдение: в 8.5 у большинства элементов пропадают ID `0x1d` и
`0x1e`, а вместо них появляется новый блок (`Form` — `0x2a`–`0x31`, `Page` —
`0x2a`–`0x2c`). Похоже, общие атрибуты элемента вынесены в базовый писатель
или переставлены; для адаптации это важнее, чем простое добавление свойств.

## Как адаптировать под новую платформу

1. Прогнать `extract` на `mngbase.dll` новой версии.
2. Прогнать `matrix`/`compare` — получить список добавленных, удалённых и
   переупорядоченных атрибутов.
3. Обновить таблицы правил и тесты в `ibcmd-rs`, подтвердить побайтовой
   выгрузкой эталонной формы.

## Ограничения

- ID атрибутов пока не сопоставлены с XML-именами: таблица «ID → имя» —
  следующий шаг (реестр в `mngdsgn`/`config` либо выравнивание по эталонной
  выгрузке с большим числом непустых свойств).
- `Field` в 8.5.1 пишет `0x35` трижды — это реальные вызовы, а не артефакт;
  требует разметки по подзначениям.
- Правила сняты только с `mngbase.dll`; писатели других объектов могут жить
  в других модулях.
- Разбор псевдокода регуляркой: при агрессивном инлайне вызов может не
  распознаться, поэтому набор атрибутов сверяется по матрице между версиями.
