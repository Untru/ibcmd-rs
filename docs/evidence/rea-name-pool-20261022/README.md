# Инвентарь имён свойств из `mngcore.dll` 8.5.1.1529

Дата: 22.10.2026. Ветка: `feat/rea-form-property-inventory-20261022`.

## Зачем

Ретроспективы проекта (24–27.07) фиксируют: семантика слотов и порядок свойств
форм выводятся из диффов с эталонной выгрузкой, а цикл «дифф → локальный патч»
исчерпан. Прежде чем снимать правила из кода писателя, нужен инвентарь имён,
которыми платформа реально пользуется, и разрыв с тем, что знает проект.

Это первый шаг, а не доказательство порядка: раскладка пула имён ≠ порядок
записи в XML. Порядок определяет код писателя, к нему — следующий шаг.

## Метод

Платформа хранит имена метаданных и свойств интернированными UTF-16-строками,
а в секции `.data` лежит массив указателей на них. Скрипт разбирает PE,
находит секцию `.data`, проходит по выровненным восьмибайтовым указателям,
проверяет, что цель лежит в образе, и декодирует UTF-16-строку до нуля.

```powershell
python tools/dump-mngcore-name-pool.py `
  --dll "C:/Program Files/1cv8/8.5.1.1529/bin/mngcore.dll" `
  --out docs/evidence/rea-name-pool-20261022/name-pool.tsv

python tools/report-form-property-coverage.py `
  --tsv docs/evidence/rea-name-pool-20261022/name-pool.tsv `
  --repo . --out docs/evidence/rea-name-pool-20261022/coverage.json
```

## Структура записи

Пул — не просто массив строк, а массив 16-байтовых записей:

```
struct Entry {           // шаг 16 байт
    const char16_t *name;         // +0  внутреннее имя
    const char16_t *presentation; // +8  русская подпись
};
```

Примеры (полностью — [descriptors.tsv](descriptors.tsv), 1 730 имён,
1 724 с подписью):

| slot | name | presentation |
|---|---|---|
| `0x1809b56f0` | `AutoMaxWidth` | `АвтоМаксимальнаяШирина` |
| `0x1809b8bb0` | `VerticalStretch` | `РастягиватьПоВертикали` |
| `0x1809b3f50` | `UsualGroup` | `ОбычнаяГруппа` |
| `0x1809b4d90` | `Title` | `Заголовок` |

Это подтверждает семантику имён и даёт словарь «имя → подпись», но по-прежнему
не порядок записи в XML: он определяется кодом сериализатора.

## Ход поиска писателя

Ссылки на слот `AutoMaxWidth` (21 адрес в `.text`) оказались не функциями, а
thunk-обёртками одного вида:

```
mov edx, r8d
lea rcx, [rip + …]      ; адрес слота имени
jmp qword ptr [rip + …] ; core::term_string
```

Цель `jmp` — импорт `core::term_string` из `core85.dll`
(`?term_string@core@@YAPEB_SQEBQEB_SH@Z`). То есть слоты читаются как элементы
терм-строк, а не сериализатором XML. Единственная ссылка на базу таблицы
(`0x180991e40`, адрес `0x180033ef2`) ведёт в такую же обёртку.

Плотность имён свойств по модулям (13 контрольных имён форм):

| DLL | Совпало | Что это |
|---|---|---|
| `mngcore.dll` | 11/13 | модель форм |
| `mngdsgn.dll` | 10/13 | дизайнер форм |
| `mngbase.dll` | 8/13 | базовая модель |
| `config.dll` | 4/13 | сериализация, пространство `xcf` |
| `backend.dll` | 4/13 | серверный слой |

Сериализатор XML ищем в `config.dll`: это единственный модуль с
`http://v8.1c.ru/8.3/xcf` и `ConfigDumpInfo`, помимо `backend.dll`.

В `config.dll` найдены строки пространств имён `http://v8.1c.ru/8.3/xcf/readable`
(`0x1802f5320`) и `http://v8.1c.ru/8.3/xcf/enums` (`0x1802f5370`). Ссылки ведут
в две функции: `0x180201f30` и `0x18022fd40` — это обвязка записи атрибутов
(пространство `http://v8.1c.ru/8.1/data/core`), а не обход свойств элемента.

Проверена гипотеза «порядок свойств задан массивом указателей на дескрипторы»:
непрерывных массивов указателей в таблицу дескрипторов нет — найдено всего
6 серий по 3+ указателя, ни одна не содержит свойств форм. Значит, списки
свойств по типам хранятся иначе (индексами или идентификаторами), и это
следующая цель.


## Как читать

- **898 из 1731** — проект уже знает эти имена; остальные 833 — кандидаты в
  непокрытые. Это не обязательно свойства форм: `mngcore.dll` держит имена
  многих подсистем, поэтому список надо фильтровать по семействам.
- **513** имён доходят до парсера форм. Разница с 898 показывает, сколько
  известно схеме и документации, но не обработчику.
- Вокруг `AutoMaxWidth` (`0x1807a2550`) пул идёт как
  `HorizontalStretch | MaxWidth | AutoMaxWidth | Width` — похоже на группу
  свойств, но подтверждать это нужно кодом.
- Ссылка на имя идёт из таблицы указателей (`PTR_u_AutoMaxWidth`,
  `0x1809b56f0`), а не из кода напрямую: искать писателя нужно по ссылкам на
  таблицу, а не на строку.

## Ограничения

- Пул содержит все интернированные имена `mngcore`, а не только свойства форм.
- Порядок в пуле не доказан как порядок XML-сериализации.
- Одна сборка платформы (8.5.1.1529); на 8.3.27 набор может отличаться.
