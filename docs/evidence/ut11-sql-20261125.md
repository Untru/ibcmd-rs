# UT11 SQL export and empty-target import, 2026-11-25

Refs #359. Measured upstream master `54b796f64da5daed3714acdf7810581fe0e58778`
with the full vendor UT 11.5.27.113 template, native 1C 8.3.27.2342 and SQL
Server 2025 17.0.1155.3 on Windows. The historical 50,898-file CF result
used UT 11.5.27.75 and platform 8.3.27.2214. The measurements below apply to
11.5.27.113 on SQL Server.

## Execution

1. Build the pinned source with `cargo +1.98.0 build --locked --release --bin ibcmd-rs`.
   This Windows build used MSVC with `CL=/utf-8` for the non-ASCII package path.
2. Use native `infobase create` to initialize the seed and a distinct empty
   target. Native `infobase config load` stages the vendor CF in the seed.
   Native `infobase config apply --dynamic=disable --force` applies the staged
   configuration. The seed then has 42,349 `Config` rows and zero `ConfigSave` rows.
3. Back up the seed with `COPY_ONLY,CHECKSUM`, verify the backup with
   `RESTORE VERIFYONLY WITH CHECKSUM`, and restore it twice under new SQL
   database names and separate data and log paths. Take the baseline fingerprint
   from each clone. For each of `Config` and `ConfigSave`, hash the binary payload
   of every row with SHA-256, then hash the ordered SQL JSON representation of
   `FileName`, `PartNo`, `Creation`, `Modified`, `Attributes`, `DataSize` and
   the payload digest. Sort by `FileName COLLATE Latin1_General_100_BIN2, PartNo`
   and retain row counts. Both clones matched before the exports and each
   matched the baseline after its export.
4. Export one clone with native `infobase config export` and the other with
   `ibcmd-rs infobase config export --platform=8.3.27`. Both use
   `--dbms=MSSQLServer --db-server=localhost --db-name=<clone>` and fresh
   output directories. The native command used its own `--data` directory.
5. Confirm that the distinct native-created target has 72 user tables and
   zero rows in both configuration tables. Run
   `ibcmd-rs infobase config import --platform=8.3.27 --report=<private-report> <ours-source>`
   with the target connection flags and default staging and verification.

SQL authentication was Windows integrated. The embedded SQL client reported
`UnknownIssuer` against the local development instance. Both measured
`ibcmd-rs` commands selected the ODBC 18 tools with `--sqlcmd`. The local
launcher accepted only `-S localhost` and passed `-C` to sqlcmd and `-u` to
bcp for that instance's certificate. No machine trust or SQL Server settings
were changed. This run measures the external SQL-client route.

## Measured result

Elapsed times are single-run wall-clock observations, including process
startup and local I/O.

| Step | Exit | Seconds |
| --- | ---: | ---: |
| Native seed CF load | 0 | 602.032 |
| Native seed apply with confirmation | 0 | 641.828 |
| Native SQL export | 0 | 1,224.500 |
| ibcmd-rs SQL export | 0 | 794.687 |
| ibcmd-rs import into the empty target | nonzero | 112.563 |

The two SQL exports each contained 51,701 files. Comparing every relative path,
byte length and SHA-256 yielded 51,700 identical files, one changed file and zero
missing or extra files. `ConfigDumpInfo.xml` was identical. The sole difference
was a data processor XML file. The native tree contained 2,190,500,677 bytes and
the ibcmd-rs tree contained 2,190,500,679 bytes.

The import reported three records that the base-free compiler could not
produce:

- Form body containing an embedded spreadsheet document with cells.
- Form body with a tail reference the writer cannot place.
- Information-register descriptor with an unresolved command reference `0`.

The target still had 72 user tables and zero rows in both `Config` and
`ConfigSave` after the rejection. Native apply and the roundtrip export require
a successful import first. The SQL roundtrip criteria of #359 remain open.

The CF, SQL backup, export trees, SQL fingerprints and per-file comparison
are retained privately. See the [acceptance runbook](../sql-ut11-acceptance.md)
for the full three-tree procedure.
