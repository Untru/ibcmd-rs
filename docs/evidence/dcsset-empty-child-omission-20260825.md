# dcsset/schema empty-child omission — второй по величине класс различий uh, 20260825

Статус: закрыт двумя коммитами (`54f69a4`, `687f316`). Разбор 18 487 расходящихся
файлов `uh` (свежий экспорт против `$D/cap/uh-r1/src`, база `d0457a6`) по
пространствам имён diff-хунков выделил 1 357 макетов (`Templates/*/Ext/Template.xml`),
чьи расхождения целиком лежат в `dcsset:*`/`dcscor:*`/`dcsat:*`/`dcscom:*` (плюс
без-префиксные схемные элементы) — второй по величине класс после потери
английских языковых элементов (не в этом скоупе).

## Метод

Свежий `cf export` (`zsh $D/kit/run.sh uh <worktree> <выход>`), построчный diff
каждого `differing`-файла против native, группировка по извлечённым из diff-строк
QName-сигнатурам (`prefix:local`). Доминирующая сигнатура — `dcsset:outputParameters`
(1 345 из 1 357 файлов). Байтовое сравнение конкретных файлов (не по счётчикам)
вскрыло реальную конструкцию.

## Находка 1: `dcsset:outputParameters` — storage хранит пустой placeholder, source его опускает

Формат-факт платформы: `settingsVariant`'s `dcsset:outputParameters` присутствует в
*storage* как пустой элемент даже когда не задан — в отличие от соседей
(`selection`/`filter`/`order`/`conditionalAppearance`), которых storage при
умолчании не хранит вовсе. Но decompiled source XML платформы никогда не несёт
`<dcsset:outputParameters/>` пустым — элемент отсутствует целиком. Если
`outputParameters` был единственным содержимым `dcsset:settings`, сам `settings`
схлопывается в самозакрывающийся тег вместо пары открыт/закрыт.

Код: `src/mssql_dump/dcs.rs`, `DataCompositionXmlWriter::write_document` — общий
транслитерирующий откат (`transliterate_data_composition_settings_document`),
который отрабатывает почти всегда для `outputParameters`, поскольку узкий
типизированный когорт (`crates/ibcmd-xml/src/dcs.rs`,
`bundled_dcs_output_parameters_policy`) признаёт только ОДНО зашитое evidence-значение
("Probe Title") — любой реальный текст названия проваливается в откат.
Писал storage-байты дословно, включая пустую заглушку.

Правка (`54f69a4`): `DcsEmptyElementAction::{OmitIfEmpty, SelfCloseIfEmpty}`,
применяются только к атрибут-свободным `dcsset:outputParameters` (омит) и
`dcsset:settings`/inline `settings` (самозакрытие) при whitespace-only содержимом.

## Находка 2: то же самое для схемных `appearance`/`inputParameters`

Без-префиксные (default DCS-schema namespace) свойства `DataSetFieldField`/`parameter`
несут тот же паттерн: storage хранит пустой placeholder, source опускает целиком.
Подтверждено на native: 0 файлов с пустым `<appearance/>` в любом написании
(самозакрытом или открыт/закрыт-пусто) во всём корпусе `uh`, при 634/364 файлах с
реальным (непустым) содержимым — умолчание опускается безусловно.

Код: `crates/ibcmd-xml/src/dcs_schema.rs`,
`rewrite_dcs_primary_schema_storage_document`/`rewrite_tokens` — общий откат для
первичного схема-документа, срабатывающий почти всегда для реальных отчётов:
оба типизированных эмиттера (`emit_dcs_inner_schema_source_document` для
`DataSetObject`, `emit_dcs_query_union_link_source_document` для Query+Union+Link)
вообще не моделируют `title`/`appearance` на уровне поля, так что любой
`DataSetQuery`-отчёт с несколькими подписанными полями (большинство реальных
отчётов) уже шёл через транслитерацию.

Первый заход правки (в составе `687f316`) обработал только форму
открыт/закрыт-пусто и полностью пропустил уже-самозакрытую форму (доказано
временной инструментацией `eprintln!`, gated `IBCMD_DEBUG_DCS_APPEARANCE`,
снята перед коммитом: 7 882 реальных срабатывания проверки, ВСЕ с непустым
содержимым — пустой случай никогда не доходил до проверки, потому что
самозакрытые storage-байты шли через отдельную, ещё не подправленную ветку).

## Находка 3: осиротевший пробельный текст перед опущенным элементом

Оба места (и `dcsset:outputParameters` в `dcs.rs`, и схемные `appearance`/
`inputParameters` в `dcs_schema.rs`) делят общий побочный дефект: текстовый узел
отступа перед теперь-опущенным элементом уже записан в выходной буфер ДО того,
как решение об опущении принято (у `dcs_schema.rs` — через отложенный `pending`
flush; у `dcs.rs` — немедленная запись `Event::Text`). Результат — осиротевшая
пустая строка на месте бывшего тега. Обе точки (обе ветки self-closing/open-close
в `dcs_schema.rs`, обе ветки `Event::Empty`/`Event::Start+End` в `dcs.rs`) теперь
обрезают хвостовые пробелы (`trim_end_matches(['\r','\n','\t',' '])`) сразу после
решения об опущении.
