# Тела форм обработок ERP УХ: ревизия корня `49`, набор команд списка, палитры цветов

База: `f34f3ae` — вершина `codex/edt-schema-reset`, на которую пакет
перебазирован. Снимки: `$D/baselines/f34f3ae/`.

Разбор участка (§1–§10) снят на прежней базе `d4544e9`, где собственный экспорт
ух до любой правки воспроизвёл снимок побайтово (exact 139 999 / differing 377 /
missing 35 / extra 0) — поэтому все гистограммы и переписи ниже сняты с того же
дерева, что и эталон той базы. Измеренный гейт §11 переснят против `f34f3ae`
уже после перебазирования.

Участок: 150 файлов `DataProcessors/**/Ext/Form.xml` из множества `differing`
ключа `uh` — крупнейший корень остатка.

## 1. Метод

Две гистограммы по всем 150 файлам, не по выборке.

* **Первое расхождение.** Побайтовое сравнение, имя элемента, открытого на
  этом смещении, с каждой стороны.
* **Полный разбор.** Построчные opcode-ы `difflib` по документам, разбитым по
  CRLF; ключ класса — множество XML-тегов, которых касается любая изменившаяся
  строка. Файл, весь разбор которого стоит на одном теге, закрывается
  починкой этого тега.

Гистограмма полного разбора по 150 файлам:

```
   71  Field / Field UseAlways / Save Field   (см. §9 — не закрыто)
    8  DataPath
    5  AutoFillCheck
    3  AllowGettingCurrentRowURL
    3  BorderColor
    3  ExcludedCommand
    2  CommandSet ExcludedCommand
    2  BorderColor TextColor
    2  Height Width
    2  Customizable
    2  HorizontalStretch
   остальные — по одному файлу на класс
```

Для классов, чей ответ зависит от разложения записи, использован
**инструментированный экспорт**: временный зонд печатал для каждой формы
`(выходной путь, объявленное число членов, первые 30 членов записи корня)` и
для каждого элемента `(выходной путь, тег, имя, первые 80 членов записи)`.
Прогон сделан по всем семи корпусам стенда, в которых есть формы (`ws` форм не
содержит). Зонд снят, в пакет не входит.

## 4. Палитры цветов: пять кодов, каждый ценой всего элемента

Нерасшифрованный код гасит **весь** цвет, а не только его имя, поэтому каждый
пропущенный индекс стоит элемента целиком.

Сведение то же, что уже закрепило веб-палитру, но поэлементное: для каждой
записи элемента, несущей ровно один кортеж цвета данного пространства, и
собственного скалярного прогона нативного элемента того же имени, несущего
ровно одно значение с этим префиксом, код и имя навязываются друг другу.

* **Пространство `1` (`win:`)** — 6 различных кодов, ни одной неоднозначности,
  четыре уже известных воспроизведены индекс в индекс. Добавлены `0` →
  `win:ScrollBar` (1 запись) и `2` → `win:ActiveTitleBar` (3 записи). Вся
  шестёрка — индексы системных цветов Win32 (`COLOR_SCROLLBAR` 0,
  `COLOR_ACTIVECAPTION` 2, `COLOR_MENU` 4, `COLOR_GRAYTEXT` 17,
  `COLOR_BTNTEXT` 18, `COLOR_3DDKSHADOW` 21).
* **Пространство `2` (`web:`)** — 46 различных кодов, ни одной
  неоднозначности; 43 из них две существующие таблицы (собственная и общая
  палитра стиля за ней) отвечают верно, включая переопределение `31`.
  Оставшиеся три не отвечал никто: `73` → `web:LightSalmon`, `80` → `web:Lime`,
  `112` → `web:PapayaWhip`.
* **Пространство `3` (`style:`)** — 25 кодов, ни одной неоднозначности и ни
  одного расхождения с существующей таблицей; менять нечего.

Закрывает 7 файлов с `<BorderColor>` и 2 с `<TextColor>`.

## 6. Картинка страницы, хранимая в самой записи

Значение картинки `Page` читается той же парой
`FormPageSchema` / `parse_form_owned_picture`, что отвечает и за ссылку, и за
прозрачность, но вид «полезная нагрузка» был исключён из неё отдельной
границей — при том что три вида различаются собственными объявленными числами
членов. Из читателя выносилась только половина «ссылка», поэтому страница с
вложенной картинкой теряла и элемент, и файл рядом с формой.

ух `DataProcessors/ОбщиеОбъектыРеглОтчетности/Forms/ФормаСозданияОтчета`,
страница `ГруппаРанееСозданные`: `{4,3,{0},"",31,15,1,{<полезная нагрузка>},0,""}`,
платформа пишет
`<Picture><xr:Abs>Picture.png</xr:Abs><xr:LoadTransparent>true</xr:LoadTransparent><xr:TransparentPixel x="31" y="15"/></Picture>`
и сам `Picture.png`. Перепись по всем восьми деревьям: это **единственная**
страница стенда с вложенной картинкой (265 у `PictureDecoration`, 111
`ValuesPicture` у `PictureField`, 108 у `Button`, 30 `RowsPicture` у `Table`,
12 `HeaderPicture` у `PictureField` и одна эта).

### 6.1 Скан активов читает запись на объявленном смещении

Файл рядом с формой пишет не читатель элемента, а отдельный скан активов, и он
адресовал запись абсолютно — то есть знал только запись без условного префикса.
Префикс `UserVisible` сдвигает каждый член записи на один, поэтому слот
картинки, который скан выбирал у префиксованной записи, — это член ПЕРЕД
картинкой. Элемент при этом писался верно: читатель элемента канонизацию уже
делал, скан — нет.

Ценой была не разница в байтах, а отсутствующий файл. ух
`DataProcessors/ВыгрузкаЗагрузкаДанныхXML/Forms/Форма`, таблица
`ДеревоМетаданных` — префиксованная запись обёртки `55`: `<RowsPicture>` в
`Form.xml` платформы совпадал, а `RowsPicture.png` рядом не писался вовсе.

Скан приведён к той же канонической записи, которую видит читатель элемента, и
картинку страницы (§6) читает через `FormPageSchema`, а не через выписанный
отдельно слот. Два файла активов, которых не было вовсе, — это ровно эти два:
`ДеревоМетаданных/RowsPicture.png` и
`ГруппаРанееСозданные/Picture.png`.

## 8. Умолчания геометрии графической схемы — закрыто вершиной, дубль снят

Этот факт пакет **не несёт**: его закрыл коммит вершины `6f25346`
(«графическая схема пишет свой блок настроек и свою геометрию»), влитый
параллельно. Он держит `50`/`10` в объявленной таблице
`FORM_DOCUMENT_FIELD_GEOMETRY` — строкой `GraphicalSchemaField`, которую от
её соседа `HTMLDocumentField` отличает не белый список тегов, а объявленное
число членов (14 против 13) при общем дискриминаторе `3`, — и подпирает пару
семенами против 8.3.27.2214: `gsx-wh` двигает ровно члены 1 и 2 (`50`→`80`,
`10`→`25`), `gsx-wh5010` хранит байты, идентичные контролю, и платформа не
пишет обратно ни одного элемента, `gsx-wonly`/`gsx-honly` двигают по одному.

Собственная перепись этого пакета — 21 запись `GraphicalSchemaField` по семи
корпусам, сведённая с элементом платформы:

| член | значение | записей | `<Width>`/`<Height>` написан |
|---|---|---:|---|
| ширина | `50` | 16 | ни на одной |
| ширина | `80` | 5 | на всех пяти |
| высота | `10` | 15 | ни на одной |
| высота | `25` / `18` / `15` | 4 / 1 / 1 | на всех шести |

Ни одна запись не расходится ни в одну сторону, и направление ответа то же,
что у вершины; переписи сняты на разных подмножествах (вершина считала 15
записей двух корпусов, где есть хранимая запись на каждое состояние), поэтому
сходятся они по знаку каждого члена, а не по одному и тому же числу записей.
Своего читателя пакет для этого факта не заводит.

**Двух чтений одного факта в дереве нет** — это проверено на слитом файле, а не
предположено: `graphical_scheme_edit` разбирается ровно в одном месте
(`parse_form_document_field_flag` по слоту 4 таблицы) и пишется ровно в одном,
а ширина и высота проходят через единственную пару
`parse_form_document_field_extent` / `FORM_DOCUMENT_FIELD_GEOMETRY`.

Заодно вершина сняла как ложное правило выведение `<Edit>` из `<ReadOnly>`:
на полной нативной популяции из 11 read-only записей 8 пишут
`<Edit>false</Edit>`, а 3 не пишут, и эти три — ровно те, у которых слот 4
держит умолчание. Флаг читается со своего слота, а не выводится из соседнего
элемента.

## 9. НЕ ЗАКРЫТО: `<UseAlways>` реквизита типа `cfg:ConstantsSet` — 71 файл

Самый крупный класс участка и самый крупный одиночный класс остатка ух.
Правило измерено точно, но сводится к именному списку из восьми констант,
поэтому в пакет **не вошло**: доктрина 7 запрещает белые списки, а механизма
за этим списком найти не удалось. Следующему — вся снятая фактура.

### 9.1 Разделение по корпусам

| корпус | блоков `<UseAlways>` на реквизите `cfg:ConstantsSet` | совпадает с платформой |
|---|---:|---:|
| `uh` | 84 | **0** |
| `ut` | 42 | 42 |
| `do` | 29 | 29 |
| `ssl` | 12 | 12 |
| `sslbase` | 12 | 12 |
| `wms` | 1 | 1 |
| `mdm`, `ws` | 0 | — |

То есть читатель верен на 96 блоках из 96 вне ух и неверен на всех 84 блоках ух.

### 9.2 Что именно расходится

Наш список — ровно объявленный список записи: `{0,<N>,{1,{0,<uuid константы>}}×N}`
в собственной записи реквизита, каждый uuid разрешается в имя константы. Через
84 блока проходит 353 различных константы, и **345 из них не расходятся ни
разу**. Расходятся ровно восемь:

| константа | и у нас, и у платформы | только в записи | только у платформы |
|---|---:|---:|---:|
| `СрокОплатыПокупателей` | 0 | 7 | 77 |
| `СрокОплатыПоставщикам` | 0 | 7 | 77 |
| `ВсегдаКонтролироватьБалансРучныхОпераций` | 0 | 15 | 69 |
| `ПутьККаталогуИмпорта` | 0 | 15 | 69 |
| `ДополнительныеЯзыкиВыводаОтчета` | 0 | 15 | 0 |
| `НастройкиКолонтитуловПоУмолчанию` | 0 | 15 | 0 |
| `ПараметрыАдминистрированияИБ` | 0 | 8 | 0 |
| `СтатусОбновленияКонфигурации` | 0 | 8 | 0 |

Первые четыре — **точное дополнение** на всех 84 блоках: платформа пишет
константу ровно тогда, когда запись её НЕ называет (7 + 77 = 15 + 69 = 84, и
«и там, и там» — ноль). Последние четыре платформа не пишет никогда, хотя
запись их называет.

Эквивалентная формулировка, сходящаяся на всех 84 без исключений:

    платформа = (запись ∖ ВОСЕМЬ) ∪ (ЧЕТЫРЕ ∖ запись)

где ЧЕТЫРЕ ⊂ ВОСЕМЬ — первые четыре строки таблицы.

Три наблюдаемых образца (69 / 8 / 7 блоков соответственно):

* запись не называет ни одной из восьми — платформа пишет запись плюс четыре
  (`DataProcessors/НастройкаДетализацииРеглУчета/Forms/ФормаНастройки`: 8 uuid в
  записи, 12 имён у платформы);
* запись называет `{Всегда, ДопЯзыки, НастрКолонтитулов, Путь}` +
  `{ПарамАдминИБ, СтатусОбновл}` — платформа пишет запись минус эти шесть плюс
  `{СрокОплатыПокупателей, СрокОплатыПоставщикам}`
  (`DataProcessors/ПанельАдминистрированияУХ/Forms/ОбщиеНастройки`: 32 uuid,
  28 имён);
* запись называет `{Всегда, ДопЯзыки, НастрКолонтитулов, Путь}` +
  `{СрокОплатыПокупателей, СрокОплатыПоставщикам}` — платформа пишет запись
  минус эти шесть (`DataProcessors/ПанельАдминистрированияУХ/Forms/
  ПланированиеИКонтроль`: 8 uuid, 2 имени).

### 9.3 Что уже отвергнуто переписью — повторять не нужно

* **Имена платформа берёт не из записи формы.** Ни `7ce2fdd1-…`
  (`СрокОплатыПокупателей`), ни `be4a7026-…` (`СрокОплатыПоставщикам`) не
  встречаются в теле формы `ПанельАдминистрированияУХ/ОбщиеНастройки` ни разу
  (`89b45415-…​.0` и `f9fa74fe-…​.0` прочитаны целиком), а платформа их пишет.
  Значит, добавка приходит из конфигурации, а не из формы.
