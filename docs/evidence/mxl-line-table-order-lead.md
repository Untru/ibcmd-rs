# Порядок таблицы линий MOXCEL: закрыто признаком покрытия

Состояние: **закрыто** правкой 2a8beb7, затем **уточнено** — покрытие само
оказалось неполным признаком, см. «Уточнение» в конце файла. История ниже
сохранена, потому что это образцовый случай правила, верного не везде.

## Как выглядела задача

Таблица линий табличного документа уплотняется при выдаче. Правка 40e8ce6
уплотняла её **в порядке первого цитирования** ячейками вместо **порядка
хранения**. Измерения разошлись по знаку:

| конфигурация | эффект 40e8ce6 |
|---|---|
| Web_Service | **+6** |
| MDM_Management | **+6** |
| БСП демо | **−1**: ломала ранее совпадавший файл |

Сломанный файл:
`Documents/_ДемоРеализацияТоваров/Templates/ПФ_MXL_РеализацияТоваров/Ext/Template.xml`.
Линии 1 и 2 менялись местами, и индексы границ ячеек начинали указывать не
на те линии: `width="2"` там, где платформа пишет `"1"`, `bottomBorder` 0
там, где платформа пишет 1.

Правка была откачена (00f6b90): прибавка в двенадцать файлов не окупает
одного сломанного, а расхождение знака означало, что правило верно не для
всех документов.

## Признак

**Переупорядочивать нужно только ту таблицу, которая что-то отбрасывает.**

* `КарточкаСчета` объявляет пять записей, цитирует четыре — отброшенная
  запись есть, и выжившие публикуются в порядке цитирования;
* `ПФ_MXL_РеализацияТоваров` цитирует обе свои записи. Первое цитирование
  называет индекс 1 раньше 0 — та же форма, что у `КарточкаСчета`, — но
  платформа публикует их в порядке хранения.

То есть порядок цитирования имеет доказательство только для таблиц с
неполным покрытием. Таблица, у которой процитированы все записи, остаётся
ровно как хранится:

```rust
if moxel_used_line_indexes(formats).len() == lines.len() {
    return (lines, None);
}
```

## Измерения после признака

Сломано **0** на всех пяти конфигурациях; прибавлено 5 на Web_Service,
5 на MDM_Management, 181 на ERP УХ. Прибавка на единицу меньше, чем давала
сплошная правка, — это ровно тот случай полного покрытия, который она
портила.

Свидетельство УТ, записанное в комментарии таблицы (604 документа, 0
расхождений по числу), не проверяло ни одну из ветвей: там каждая запись
была и процитирована, и уже сохранена в порядке цитирования.

## Уточнение: полное покрытие — не всегда стабильный порядок

ERP УХ `Web_Service`/`MDM_Management`'s
`DataProcessors/УниверсальнаяОтчетностьПоРегистрамУХ/Templates/ОтчетПоПроводкам/Ext/Template.xml`
объявляет пять записей, цитирует все пять (полное покрытие) — и всё равно
не публикуется в порядке хранения. Платформа пишет `[None/1, Solid/2,
Solid/1, ThinDashed/1, Dotted/1]`, а хранится `[None/1, Solid/1, Solid/2,
Dotted/1, ThinDashed/1]`; это ровно порядок цитирования этой функции
(`compact_moxel_line_table`'s собственный проход по `formats` в порядке
пула и `border, left, top, right, bottom, drawing` внутри каждого).

Различие с `ПФ_MXL_РеализацияТоваров` (и двумя такими же документами
1С:УТ 11.5.27.75 — `ПФ_MXL_ПриемкаТоваровНаХранение`,
`ПФ_MXL_ПоступлениеТоваров`, оба тоже полное покрытие, оба остаются в
порядке хранения): у всех трёх «ломающихся» документов первая *хранимая*
запись — не первая *процитированная* (`order[0] != 0`, обычно индекс 1
цитируется раньше 0). У `ОтчетПоПроводкам` первая хранимая запись и есть
первая процитированная (`order[0] == 0`), и именно на этой оси
дискриминатор:

```rust
if full_coverage && (order.first() != Some(&0) || order.iter().copied().eq(0..lines.len())) {
    return (lines, None);
}
```

Полное покрытие само по себе не решает; решает — является ли первая
хранимая запись также первой процитированной. Признак «покрытие» остаётся
верным для входа в это правило (без него ни партиционная, ни полная ветка
не имеют доказательства), но для полного покрытия он не единственная ось.

Измерено равенством множеств на всех семи конфигурациях стенда:
`ws` 28/29 → **29/29**; `mdm` +1 (`ОтчетПоПроводкам`); `sslbase`/`ssl`/`ut`
— 0 сломано, 0 прибавлено (ни один из трёх контрпримеров не задет); `uh`
— 0 сломано, **+3**: `ОтчетПоПроводкам`, `Documents/ОперацияМСФО/Templates/
БухгалтерскаяСправка`, `Reports/РегламентированноеУведомлениеИнформация
ОПараметрахДоступаИС/Templates/ПечатныйБланк_2023` — конструкция
действительно общая, не привязана к одному объекту.

Регрессионный тест: `full_coverage_line_table_reorders_when_first_entry_is_first_cited`
(`src/mssql_dump/tests.rs`), на реальном захваченном теле
(`tests/fixtures/moxel_transaction_report_line_order_raw.txt`).
