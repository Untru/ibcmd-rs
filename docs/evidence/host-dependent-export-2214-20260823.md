# Вывод платформы зависит от операционной системы хоста

Платформа: **8.3.27.2214**. Конфигурация: «1С:Управление торговлей 11.5.27.75».
Дата наблюдения: 23.08.2026.

## Что наблюдалось

Эталонное дерево round-2, по которому выводились все правила проекта, снималось
на **Windows**. 23.08.2026 та же конфигурация той же сборкой платформы была
выгружена на **macOS** (`ibcmd infobase create --load=<cf>` →
`ibcmd infobase config export`), и обе выгрузки дали ровно 50 898 файлов.

Наш экспорт, совпадающий с Windows-выгрузкой на 50 890 файлах, против
macOS-выгрузки совпадает только на 50 451. Разница — **439 файлов**, и все они
расходятся не по нашей вине.

## Две конструкции, которые платформа пишет по-разному на разных хостах

### 1. Модификатор в `<Shortcut>` — 437 файлов

| хост | пишет |
|---|---|
| Windows | `<Shortcut>Ctrl+S</Shortcut>` |
| macOS | `<Shortcut>Cmd+S</Shortcut>` |

Проверено построчно: из 439 файлов **437 расходятся только строками
`<Shortcut>`**, других различий в них нет.

### 2. Автоматическое имя серии диаграммы — 2 файла

`DataProcessors/ПроверкаКонтрагента/Templates/ФинансовыйАнализ` и
`Reports/ДосьеКонтрагента/Templates/ФинансовыйАнализ`.

| хост | пишет |
|---|---|
| Windows | `<v8:content>Pivot</v8:content>` |
| macOS | `<v8:content>Сводная</v8:content>` |

Хранимое имя серии в обоих случаях одно и то же — `Сводная`; различается то,
что платформа публикует, когда флаг «имя изменено» снят. На Windows она пишет
автоматическое имя в английском написании, на macOS — хранимое.

## Почему это важно

1. **Наш паритет 99,9843 % измерен против Windows-эталона и остаётся верным.**
   Обе расхождения выше — это места, где наш вывод совпадает с Windows и не
   совпадает с macOS.
2. **Выгрузки с разных хостов не взаимозаменяемы.** Дерево, снятое на macOS,
   нельзя подставить вместо round-2 без учёта этих двух конструкций: получится
   439 фантомных расхождений, ни одно из которых не является дефектом.
3. **Любой новый захват должен фиксировать хост.** Манифест обязан нести
   операционную систему выгрузки наравне с версией платформы.
4. Для конфигураций, которые захватываются на macOS (ERP «Управление
   холдингом», БСП и прочие), паритет считается против macOS-эталона, а
   host-зависимые конструкции выделяются в отдельную категорию и не считаются
   расхождениями.

## Чего наблюдение НЕ говорит

Оно не говорит, какое из двух написаний «правильное»: оба написаны платформой,
и оба верны для своего хоста. Оно не говорит и того, что host-зависимых
конструкций ровно две — оно говорит, что на этой конфигурации их проявилось
две. Другая конфигурация может проявить больше.

## Как воспроизвести

```
ibcmd infobase create --data=<dir> --load=<cf>
ibcmd infobase config export --data=<dir> <outdir>
```

Обе команды — платформа 8.3.27.2214, одноразовая изолированная файловая ИБ.

## Поправка 25.08.2026: `<Shortcut>` был нашим дефектом, а не host-зависимостью

Пункт 4 выше предлагал выделять host-зависимые конструкции в отдельную
категорию и не считать их расхождениями. Для `<Shortcut>` это оказалось
лишним: мы просто писали чужое написание.

В блобе лежит host-НЕЙТРАЛЬНАЯ маска модификаторов — тот же кортеж
`{0, virtual-key, modifier-mask}` в том же `.cf` на любом хосте. Меняется
только то, как платформа её произносит: бит 8 — `Ctrl` на Windows и `Cmd` на
macOS, бит 16 — `Alt` и `Option`. Бит 4 остаётся `Shift`, имя клавиши не
меняется, порядок модификаторов одинаков.

Наш `parse_common_command_shortcut_value` жёстко печатал `Ctrl`/`Alt` на любом
хосте. Все эталонные деревья стенда — macOS-захваты: 2 900 `Cmd` и 140
`Option` в uh/ut/ssl/sslbase и **ни одного** `Ctrl` или `Alt`. Мы работаем на
macOS, то есть печатали написание того хоста, на котором не находимся.

Доказательство подстановкой (БСП базовая, 81 форма с `<Shortcut>`): 50 уже
совпадали побайтово, остальные 31 становятся побайтово идентичными эталону
ровно под заменой `Ctrl`->`Cmd`, `Alt`->`Option`, остатка нет.

После того как рендер стал следовать хосту (`ShortcutModifierStyle::host()`):
ut 50 456 -> **50 894** (+438), расхождений осталось 4 из 50 898 (99,9921 %);
uh +692; sslbase +33; ssl +40; СЛОМАНО = 0 везде. То есть 437 файлов, которые
этот документ числил «не дефектами», были дефектом одной строки.

**Что из документа остаётся верным:** наблюдение само по себе, обе таблицы
написаний, требование фиксировать хост в манифесте захвата и то, что выгрузки
с разных хостов не взаимозаменяемы. Неверен только вывод, что расхождение
непоправимо с нашей стороны: платформа зависит от хоста — значит и мы должны,
и тогда совпадение точное.

**Второй случай (имя серии, 2 файла) остаётся открытым** и, судя по всему,
лечится тем же способом: хранимое имя одно (`Сводная`), Windows публикует
английское автоматическое, macOS — хранимое; на macOS нам следует публиковать
хранимое. Это Templates/MXL, вне текущего наряда — но это ровно те 2 файла из
4 оставшихся расхождений ut (два других — GanttChart).
