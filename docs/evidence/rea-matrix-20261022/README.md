# Бухгалтерия 3.0 на 8.5.1.1529: итог исследования

Сжатая версия журнала из 95 раундов (22–23.10.2026). Полный журнал с
трассировками и отрицательными попытками остался в ветке
`feat/rea-form-property-inventory-20261022`, тот же путь, коммит `d18daab9`.

## Стенд и метод

- Конфигурация `Accounting_3_0_199_13.cf` (750 МБ), база `ibcmd_acc2` на
  MS SQL Server, платформа 8.5.1.1529, XML 2.21.
- Нативный `ibcmd` и `ibcmd-rs` выгружают одну и ту же базу; файлы
  сравниваются побайтово по SHA-256 (`tools/rea/matrix_parity.py`). Деревья
  в репозиторий не кладутся.

## Доказанные правила

Основание каждого — совпадение с нативным XML и тест на фикстуре:

- команды root-42: тег `8`, 18 членов, `CurrentRowUse=DontUse` (13 из 13);
- теги таблиц `50`/`53` в списке ведущих членов: без них запись
  отбрасывалась на входе;
- `UseAlternationRowColor=true` снимает лишний BWA во 2.21-проходе;
- fallback пути картинки строки идёт после фильтра пустой строки (ошибка
  `or_else` на `Some("")`);
- все шаги таблицы «Путь» выше, кроме строки «константы 4–5».

## Гипотезы раскладки (в коде, помечены)

Подобраны под одну списковую форму, работают только на таблицах `50`/`53`,
которые master отбрасывал целиком:

1. удаление члена 15 у записи тега `53`;
2. удаление последнего члена;
3. подавление `GroupHorizontalAlign`/`GroupVerticalAlign` у legacy-таблиц
   (ничего не выдумывает, только не пишет).

1–2 выравнивают поздние слоты (DefaultItem 16, InitialTreeView 39,
EnableStartDrag 52): без них те же чтения дали бы неверные значения, а не
пропуски. Сужение обрезки до 150-членной записи давало регрессию 609 → 642.
План доказательства: цензус вариантов записи тега `53` (150 и 131 член) по
корпусу и сверка с декомпилированным писателем форм.

## Убрано из этого PR

- константы для legacy-таблиц `ChoiceFoldersAndItems = Items` и
  `RowPictureDataPath = <путь>.DefaultPicture`: значение подставлялось без
  чтения записи (вместе давали −34 файла);
- XDTO-модель logform, контракт порядка атрибутов, пул имён `mngcore`,
  правила писателей из `mngbase`, скрипты Ghidra и генераторы: на выгрузку
  не влияли, данные извлечены из DLL платформы.

## Отличия этого PR от исходной ветки, влияющие на счёт

- палитра web-цветов: три пары возвращены к кодам, подтверждённым корпусом
  (70 LightGreen, 71 LightGray, 77 LightSlateGray, 96 Moccasin);
- V2-формы (4 формы планов обмена) по умолчанию дают отказ: платформа
  достраивает в них таблицу, которой нет в записи. Записать их неполными
  можно только явно: `IBCMD_RS_ALLOW_INCOMPLETE_V2_FORMS=1`;
- связи 5004: legacy-разбор только там, где отказал схемный, и только при
  пустом зеркале `5007`; префикс пути — имя реквизита 1, а не `Объект`;
  неоднозначная колонка пишется физическим путём;
- таблицы внешних источников принимаются только в измеренной форме записи
  (ServiceDesk 3.10.28), иначе отказ.

## Отрицательные результаты (не повторять)

- глобальная дедупликация `<merge>` и дедупликация «между списками»:
  736 → 761, платформа сама печатает повторяющиеся регионы;
- обрезка «лишнего члена в хвосте» записи `50` без других правок: эффекта нет;
- ранний приём `FormTableSchema` для тега `53`: схема падает на слоте 12
  (составной `Autofill`);
- отключение 2.21-прохода для legacy-тел: регрессия;
- `CheckBoxType` через смещение `("33", 56)` и fallback «12 членов → слот 4»:
  без эффекта;
- карта полей `UseAlways` как источник имён: имя приходит не оттуда;
- палитра из `core85.dll` как единственный источник кодов: переставляет
  соседние пары, корпус её опровергает.

## Открытые классы расхождений

Лишний `<ExcludedCommand>` в третьем `CommandSet` таблицы; `SetDateInterval`;
`CheckBoxType` у записи `{33,…}`; `UseAlways` без имени; поздние слоты
legacy-таблиц; ограничение корня привязки в root-46.
