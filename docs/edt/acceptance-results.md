# Фактические результаты стенда EDT

Эта страница сохраняет исторические неудачные запуски вместе с последующими
проверками. Нижеприведённый отказ кандидата `a09b1c23` не описывает ограничения
текущей реализации. Ограничение числа XML-событий, квоты размера исходных
скаляров, графа, путей, обычных форм и справки уже устранены в явном режиме
обработки исходников. Завершённая приёмка всей конфигурации пока не объявлена.

Последующие отдельные проверки прошли:

- Настоящий экспорт EDT после исправления владельцев обработчиков форм и
  динамических таблиц: все 12 197 файлов БСП совпали с эталоном побайтно.
  Доказательство: `bsp83-generated-table-owner-causal-r4/sdk-export-r1`.
- Полная семантическая проверка 1 108 форм БСП: расхождений нет.
  Доказательство: `bsp83-table-event-semantic-census-r2.json`.
- Обе конверсии СКД с CDATA, сущностями и разделёнными QName проходят
  независимое чтение без provenance и точный возврат неизменённого оригинала.
  Доказательства: `dcs-qname-directory-independent-review-r1.log` и
  `dcs-source-projection-independent-review-r1.log`.
- Обычные формы, страницы справки и ресурсы крупнее 32 МиБ сохраняются в обоих
  диалектах. Доказательство: `sdk-source-bodies-controls-r5.log`.
- Физическое имя ресурса из 260 байт UTF-8, допустимое в Windows, сохраняется
  в обеих конверсиях и при чтении без provenance.
  Доказательство: `source-windows-filenames-independent-review-r1.log`.
- Core сохраняет явную связь UUID перечисления с его собственным типом
  `EnumList.<Name>`, не разрешая посторонние дубликаты. Все 26 реальных
  случаев УХ 8.3/8.5 независимо проверены при чтении и точном возврате XML;
  полный анализ четырёх корпусов не обнаружил других видов совпадения UUID.
  Доказательства: `uuid-taxonomy-readonly-r1`,
  `core-enum-alias-evidence-independent-review-r1.json` и
  `source-enum-alias-independent-controls-r1.log`.

Повторяемый контроль диагностики использует отдельную свежую копию проекта
и одинаковое число проходов исходного и сгенерированного проектов. Все строки
TSV сравниваются точно, включая предупреждения и стиль кода. Все записи журнала
EDT сохраняются; только идентичность JVM в одиннадцати точно определённых
сообщениях регистрации и запись команды, полностью совпадающая с проверенными
аргументами текущего прохода, имеют отдельное структурное сравнение.
Для stdout Xtext отдельно распознаётся одно точное сообщение `WARN`
`AbstractLexerBasedConverter` об использовании правила `ID`: сравниваются
полный текст, logger, severity и число записей каждого прохода; контекст
времени и номер `derived_data_executor` сохраняются в исходных журналах.
Ни другие предупреждения, ни диагностика проекта этим правилом не допускаются.
Новые сообщения, изменённые тексты и неполные записи блокируют приёмку.
Доказательство независимого ревью стенда:
`warm-all-entry-scope-independent-review-r1.json`.

Все названные доказательства находятся в `F:\ibcmd\lab\07`. Эти проверки
не заменяют итоговый прогон общего неизменяемого кандидата на БСП и УХ.

## Повторный полный прогон УХ и проверка дескрипторов

Полный аутентичный проект УХ XML 2.20 (106 260 файлов, 9 713 838 896 байт)
повторно проверен кандидатом `5a76557a`, release SHA-256
`037ae9b565a3b9ab35a254da1a2e6827bc0895ed970f771fd66b838fb22f41b5`.
Команда EDT → XML завершилась **FAIL**, exit 2, за 1 196,860 с;
выходное дерево не опубликовано. Полные SHA-инвентари до и после совпадают.
Доказательство: `convert-uha83-5a765-full-pair-r2`, исходный отчёт
`authentic-edt-to-native-xml.report.json` и
`first-route-blocker-classification.json`. Эта попытка обнаружила конкретные
неподдержанные поля семи видов метаданных, а не отказ по размеру исходников:
вспомогательные формы, справку общей команды, типы входящих запросов обмена,
пространства имён критерия отбора и опущенный режим блокировок операции.
Этот исторический отказ сохраняется при исправлении каждого пробела.

Исправления критериев отбора и веб-сервисов отдельно проверены по всем
16 и 20 объектам каждого из двух настоящих корпусов УХ 8.3/8.5.
Исходные EDT и native XML дескрипторы восстанавливаются побайтно.
Вложенные параметры WebService используют правильный физический QName-префикс
`d8p1`; возвращаемый тип операции использует `d6p1`. Семантика URI и имени
типа остаётся общей для двух форматов. Веб-сервисы содержат 224 операции:
два опущенных EDT значения соответствуют native `Automatic`, остальные
222 явных значения — `Managed`. Доказательства:
`sparse-metadata-genuine83-r6.log`, `sparse-metadata-genuine85-r1.log`,
`web-service-operation-default-proof-r1.json` и независимый
`sparse-web-service-independent-source-proof-r1.json`.
Проверка дочерних ссылок форм здесь ограничена возможностями отдельного
дескриптора: native хранит ссылку по имени, а свойства формы загружает из
отдельного файла. Итоговая проверка каталога обязана загрузить все эти файлы.
Полная приёмка общего кандидата этими отдельными проверками не заменяется.

Назначение формы сохраняется как текущий упорядоченный список во всех видах
ссылок на формы. В XML 2.20 и 2.21 проверены пустой список, только компьютер,
только мобильное устройство и оба порядка пары; обе конверсии проходят
с provenance и без него.
Изменение назначения после повторного вычисления хеша provenance не позволяет
вернуть старые значения, а неизвестные значения и лишняя структура блокируют
публикацию. Доказательства: `form-purpose-checkpoint-r1.json` и
`form-purpose-subsets-independent-r1.log` и
`form-purpose-subsets-two-profiles-r4.log`; три публичных теста находятся в
`crates/ibcmd-edt/tests/form_purpose_subsets.rs`.

Отдельно проверены текущие свойства картинки команды метаданных: ссылка,
признак локализуемого текста и координаты прозрачного пикселя. Включены
подлинная команда УХ, совместное изменение ссылки и свойств, пустая ссылка
с непустыми свойствами, подмена хешей и удаление владельца. Все пять проверок
прошли также независимо: `metadata-picture-independent-controls-r2.log`.
Совместимость дополнительного типизированного ресурса с импортом полного
проекта установленным EDT остаётся отдельным обязательным шагом.

Справка сохраняет полный текущий список языков и порядок страниц для корня,
метаданных и ссылок на формы. Публичная конверсия проверена с provenance,
без него и после смены языка страницы; подмена всех хешей не позволяет
восстановить устаревшую справку. Пять новых проверок и регрессия по 2 152
настоящим дескрипторам Config/CommonCommand прошли независимо:
`multilingual-help-independent-controls-r2.log` и
`multilingual-help-config-regression-independent-r2.log`.
Загрузка и сохранение двух страниц штатным `FormattingXmlResource` EDT
сохраняют Ecore-семантику: `multilingual-help-research-r1/loader-r12`.
Эта проверка сериализатора не заменяет импорт полного проекта в EDT.

## Историческая попытка ERP УХ, XML 2.20 / платформа 8.3.27

Проверка от 2026-10-01 использует исходную полную выгрузку ERP УХ, аутентичный
проект установленной EDT и отдельную нативную выгрузку из свежей лабораторной
базы, куда импортирован результат экспорта этого EDT-проекта. Источники
остаются неизменными; все рабочие каталоги и доказательства находятся на F:.

Точные инструменты: EDT **2025.2.3.30**, нативный SDK **8.3.27.2214**.
Кандидат: `F:\ibcmd\lab\07\candidates\a09b1c23-final-r2\ibcmd-rs.exe`;
SHA-256: `208c22e543f29e5c5c494311c602824e2156738252efef0eb2cbe44a2f3a9bd8`.
Команды продукта используют явные профили `xml-2.20` и
`edt-2025.2.3-xml-2.20` и общий FIFO-замок лаборатории.

Оба фактических направления завершились **FAIL на decode**; выходные деревья не
опубликованы. Проверки полного сравнения, импорта сгенерированного проекта в
установленную EDT и неизменённого точного возврата не достигнуты.
