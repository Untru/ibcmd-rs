# SQL Server 2012 direct import implementation plan

> **For agentic workers:** Use superpowers:subagent-driven-development for the independent transport and import tasks. Keep one Cargo command running at a time in this checkout.

**Goal:** Make the existing native-TDS full-folder import route usable on SQL Server 2012 without native XML/CF loading, while preserving import verification and transactional ConfigSave publication.

**Architecture:** Preserve the original encrypted transport and JSON paths by default. Opt into SQL Server 2012 with `IBCMD_RS_MSSQL_COMPATIBILITY=2012`; freeze this and the encryption policy per pool. The first connected query checks actual ProductVersion major 11 before session setup or commands. Only the verified compatibility client uses typed rows for three import metadata reads; all other clients and sqlcmd retain the original paths.

**Tech stack:** Rust 1.95.0, existing tiberius/tokio/serde dependencies. No new dependencies.

**Spec:** `openspec/changes/support-sql2012-import/` and upstream issue #572. The contribution is a draft until the merge gate and maintainer acceptance are complete.

## Global constraints

- Work only in this isolated utility checkout; ERP source files and its v8project files are not implementation targets.
- Compatibility is explicit and limited to actual SQL Server 2012 (four numeric ProductVersion components, major 11). Reject invalid/empty/non-Unicode selectors before connecting and other server versions before session setup or writes. A newer server with database compatibility level 110 is rejected.
- No automatic TLS downgrade, no credential output, no changes to the default `required` encryption policy.
- `IBCMD_RS_MSSQL_ENCRYPTION` accepts `required`, `login-only`, `disabled`; unknown, empty and non-Unicode values fail before connecting. Non-required modes require the explicit 2012 selector. `disabled` explicitly means unencrypted TDS, including login.
- No new SQL parser or generic FOR JSON rewriting. Replace only the three native import reads identified in the call graph.
- No new own-apply profile, no whole-blob HASHBYTES workaround, no force, no disabled source verification.
- Do not claim new generation/drift protection: preserve the existing coordinated-use requirement and guards.
- Keep read-only connection evidence separate from write acceptance. Run against an explicitly authorized test target; document any acceptance-environment limitation against the upstream disposable-copy policy.
